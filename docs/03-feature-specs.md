## F-01 Measuring proxy — P0 — Owner A — FR-01, FR-02

**Story:** As an operator I want every LLM call by any agent to be logged with tokens, cost and latency without changing the agent.
**Input:** OpenAI chat-completions request at `POST /runs/{run_id}/v1/chat/completions` [P-02] ([08](08-api-contracts.md) §2); optional `X-Agent-Role`.
**Output:** upstream response passed through unchanged; events written ([07](07-data-schema.md) §3).

Behaviour
1. Look up run by `run_id` (must exist in `runs`, state `running`).
2. Apply faults for the run's `scenario` (provider group) before/after forwarding (F-10).
3. If `stream=true` and request lacks `stream_options.include_usage`, add it (A-02); stream chunks through to the client.
4. Forward to Bifrost; measure latency (ms).
5. Write `llm_call` event (status code, model, tokens_in/out, cost, cost_confidence, finish_reason); write one `tool_call` event per entry in `choices[].message.tool_calls` (or streamed equivalent).
6. Cost = tokens × `pricing.yaml` entry effective on the run date; missing `usage` → `estimated` via tokenizer (A-08, P1; P0 stores `null` tokens + `null` cost + `cost_confidence=estimated` and a warning: an unknown cost must not be recorded as 0, because the stats engine averages recorded costs).

States: n/a (stateless; run state owned by orchestrator).
Errors: unknown/finished `run_id` → 404 (OpenAI-shaped error body); upstream unreachable/5xx not injected → pass status through and tag the `llm_call.error` as `upstream` so the orchestrator can classify INFRA_ERROR; DB write failure → request still forwarded, error logged to stderr (never block the agent).
Edge cases: very large bodies (store payload truncated, see 07 §3); agent sends non-chat endpoints (e.g. embeddings) → forwarded, logged as `llm_call` with `payload.endpoint`; concurrent runs share one proxy; clock skew none (proxy stamps `ts`).
Dependencies: DB, Bifrost (or `mock_llm`), `pricing.yaml`.
Verification: T-01…T-05.
DoD: DoD-0 + manual call with a run ID appears in `events` with correct tokens/cost (plan Stage 2 check).

## F-02 Task library & validator — P0 — Owner B (hand-written tasks by B; generated by A via F-17) — FR-03, FR-16

**Story:** As a task author I want to drop a folder and have it rejected unless it is a sound benchmark task.
**Layout:** `prompt.md`, `workspace/`, `grader.yaml`, `reference_solution/` (plan) + `task.yaml`, `hidden_tests/` [P-13]. Field shapes: [07](07-data-schema.md) §5.
**Validator:** `validate(task_dir)` → `{ok, checks[]}`: (1) workspace + grader → **FAIL**; (2) workspace overlaid with `reference_solution/` → **PASS**; (3) grader.yaml parses; (4) protected files exist. CLI wrapper for local use.
**Seed loader:** loads validated task dirs into `tasks` table (`validated=true`, `task_hash`).
P0 content: 8-10 coding tasks (first 3: fix bug, add function, fix failing test), each with visible, hidden and (where sensible) property-based pytest tests; mix of hand-written and mutation-generated (F-17). Author checklist in [10](10-integration-contracts.md) §3.4.
Errors: validator returns `ok:false` with failing check names; seed loader refuses non-validated tasks.
Edge cases: nondeterministic tests (validator runs grader 2× and requires identical outcome); tasks needing network (disallowed in P0).
Verification: T-06, T-07. DoD: validator accepts all 5 tasks and rejects a deliberately broken task fixture (AC-06).

## F-03 Runner & sandbox — P0 (subprocess first, then hardened Docker) — Owner B — FR-04, FR-15

**Story:** As an operator I want an agent run in isolation with identical inputs and a captured diff.
**Input:** `RunSpec` ([10](10-integration-contracts.md) §2.1). **Output:** `RunResult` (exit code, timed_out, diff, stdout/stderr tail, sandbox_error?).
Behaviour (P0): create temp dir; copy `workspace/`; apply instruction fault (F-10) if scenario requires; export env vars ([10](10-integration-contracts.md) §2.2); spawn agent per manifest (`mode: command`); enforce wall-clock timeout (default 300 s, OQ-05-adjustable per task); on end compute diff vs original; always clean up.
P0 (after subprocess works): same interface in hardened container: non-root, read-only root fs, CPU/mem limits, no Docker socket, network only to proxy; emit `command` / `file_write` / `net_attempt` events from the monitor; blocked network attempt logged.
States: `queued → running → done` (state column owned by orchestrator).
Errors: spawn failure/unwritable temp dir/Docker unavailable → `sandbox_error` → orchestrator classifies INFRA_ERROR; agent non-zero exit → not INFRA (grader decides); timeout → `timed_out=true` → FAIL.
Edge cases: agent leaves child processes (kill process tree); Windows path/quoting (A-06); huge diff (truncate stored diff).
Verification: T-08, T-09. DoD: dummy agent runs; its env vars are correct; diff captured; non-proxy network call blocked and logged.

## F-04 Grader — P0 — Owner B — FR-05

**Story:** As a judge I want pass/fail I can trust.
**Input:** task dir + workspace dir. **Output:** `GradeResult` ([10](10-integration-contracts.md) §2.3): `passed`, `tamper_detected`, per-suite results, summary.
Behaviour: copy workspace to clean dir; restore `protected_files` from the original task; hash-compare to detect tamper; run visible + hidden pytest ([07](07-data-schema.md) §5.2); passed = all suites pass and no tamper. Config per `grader.yaml`.
Errors: pytest crash/timeouts → `passed=false` with `details.error`; grader infrastructure failure (cannot create dir) → raise → orchestrator INFRA_ERROR.
Edge cases: agent deleted tests (tamper); agent added extra test files (ignored); hidden tests importing from workspace paths.
Types: only `pytest` in P0; `answer_match`, `json_fields` in F-14 (P2).
Verification: T-07, T-10. DoD: tamper fixture flagged; reference solution passes.

## F-06 Benchmark orchestrator — P0 — Owner B — FR-07, FR-09, FR-21

**Story:** As an operator I want to launch a matrix and trust it to finish, resume and stay in budget.
Behaviour [P-14]
1. Poll DB for `benchmarks.state='queued'`; set `running`.
2. Expand config → slots = agents × tasks × scenarios × `repeat_index` (1..n_runs). Insert `runs` rows (`state=queued`, `attempt=1`) idempotently (unique key, [07](07-data-schema.md)).
3. Execute slots with bounded parallelism (default 2, configurable; A-05 rate limits).
4. Per slot: set `running`, build env fingerprint, call runner (F-03), then grader (F-04), then **finalise** the run row from events (P-03): tokens, cost, steps, tool_calls, duration, status.
5. **Classification (D-03):** `INFRA_ERROR` if sandbox_error, grader infra failure, or any `llm_call` flagged `error=upstream` that was not an injected fault *and* the agent produced no successful call after it; `FAIL` if timeout, tamper, tests fail, or agent exit ≠ 0 without diff; else per grader. Injected faults never cause INFRA_ERROR.
6. INFRA_ERROR → new attempt (max 3, then slot counted as `excluded`).
7. After each run: sum benchmark cost; if ≥ `spend_cap_usd` → stop scheduling, `state='halted_spend_cap'`.
8. Resume: on start, `running` runs with no live process are reset to `queued`; `done` slots are skipped.
9. When all slots resolved: `state='completed'`.
Errors: DB down → backoff and retry; unknown agent/task id in config → benchmark `failed` with `error`.
Edge cases: duplicate launch of same config (allowed, new benchmark); cap reached mid-parallel batch (in-flight runs finish, overshoot possible — documented limit); process killed mid-run (resume).
Verification: T-13, T-14. DoD: 2×3×5 benchmark survives forced kill and resumes (plan Stage 6 check; AC-05).

## F-07 Stats engine — P0 — Owner A — FR-08

**Input:** finished runs for a filter (benchmark, scenario, agent, task). **Output:** `ResultRow` ([08](08-api-contracts.md) §3.5).
- Pass rate = PASS / (PASS + FAIL); Wilson interval 95%.
- For cost, steps, tool_calls, duration: mean, median, std (population vs sample: **sample**), bootstrap CI of the mean (95%, 1000 resamples, fixed seed) — values are proposals tuned at implementation; must be documented in the Limitations page.
- INFRA_ERROR rows excluded from stats; count returned as `infra_excluded`.
- `cost_confidence` summary: counts of verified vs estimated.
- Resilience: per (agent, scenario): pass rate under fault ÷ baseline pass rate (P-16).
Edge cases: n=0 → nulls (never 0%); n=1 → CI null for non-proportions; all pass/fail → Wilson still defined.
Verification: T-15 (golden numbers). DoD: unit tests against hand-computed examples.

## F-10 Fault injection & resilience — P0 — Owner A (provider) / B (instruction, runner side) / C (tool via shared tools) — FR-12

Catalog: YAML under `faults/` (shape: [07](07-data-schema.md) §7). Run's `scenario` = fault id or `baseline`. Faults seeded from `hash(run_id)` so they are reproducible.

| Fault id (P-12) | Group | Layer | Behaviour |
|---|---|---|---|
| `provider_503_outage` | provider | proxy | first 3 requests of the run get HTTP 503 (OpenAI-shaped error), then pass through |
| `provider_429_ratelimit` | provider | proxy | first 2 requests get 429 with `Retry-After: 1`, then pass |
| `tool_run_tests_error` | tool | agent env (`ARENA_TOOL_FAULT`) [P-08] | shared `run_tests` tool returns an error on its first 2 calls |
| `instruction_misleading_hint` | instruction | runner (pre-run workspace edit) | adds a plausible but wrong hint file/section to the workspace; content defined in the fault YAML |

Every injection writes a `fault_injected` event. Tasks list allowed faults in `task.yaml.faults_allowed`; orchestrator rejects disallowed combos at launch.
Resilience score and failure view: F-07, [05](05-ux-spec.md) S5. Report text states the limit: *tests resilience under chosen conditions, not production failures* (D-10).
Errors: fault YAML invalid → loader fails at startup (fail fast). Edge cases: run finishes before fault threshold (e.g., agent makes only 1 call under `provider_503`) — still counts; `fault_injected` events tell what actually fired.
Verification: T-20, T-21. DoD (Milestone 3): dashboard shows the same agent under baseline and each fault.

## F-11 Registry & `agent doctor` — P1 — Owner B (CLI/core), C (UI form) — FR-13

`register <path-or-git-url>`: read `agent.yaml` or auto-detect entrypoint (`agent.py`, `package.json`, `Dockerfile`); insert `agents` row. `doctor`: dry-run agent on a trivial built-in task with `mock_llm`; report checks (manifest valid, entrypoint runs, uses `OPENAI_BASE_URL` — i.e. ≥ 1 proxy call observed, exits within timeout). Implements all four connection modes per plan Stage 9: `command` (executable + env vars), `http` (platform POSTs the task to an endpoint), `docker` (bring-your-own image), `proxy-only` (any agent that accepts a base URL). Build order: command, proxy-only, docker, http; `doctor` flags incompatibilities per mode.
Errors: invalid manifest → list of problems, nothing inserted. Edge: agent hard-codes provider URL → doctor reports "no proxy traffic observed" (documented limit).
Verification: T-22. DoD: one command registers; doctor flags deliberately broken manifest (plan Stage 9 check).

## F-12 Security baseline — P2 — Owner B (canary, tasks), A (score API); the monitor itself ships in F-03 (P0) — FR-14

Detect: canary string in any `llm_call` request body or in workspace diff/network attempt; writes outside workspace; destructive commands (P1 Docker monitor); blocked network attempts. Static scan with Bandit/Semgrep on diff (stretch). Security score = share of security tasks passed without violation (definition finalised with implementation; documented).
Verification: T-23. DoD: obedient agent flagged, well-behaved agent not (plan Stage 12 check).
